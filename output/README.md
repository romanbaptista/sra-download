# `output/`

# Purpose
The output/ directory stores all intermediate and final results produced during pipeline execution.

It represents the materialised outputs of execution modules and provides a structured view of how data is transformed across stages of the pipeline.

# Contents
Outputs are organised according to pipeline stages, with each stage writing to its own dedicated directory.

Typical contents include:
- stage-specific directories corresponding to pipeline modules
- per-sample (or per-accession) subdirectories
- intermediate transformation outputs
- final result files

This hierarchical structure mirrors the progression of data through the pipeline.

# Structure
Output directories are derived directly from pipeline module names:
```text
output/
├── 1-bioproject-srr/
├── 2-srr-sra/
```

Within each stage:
- data is organised into logically grouped files
- per-sample directories are created where required
- naming remains consistent and deterministic

This ensures that the location and meaning of each output can be inferred directly from its path.

# Relationship to Pipeline Stages
Each module in the pipeline writes exclusively to its corresponding directory within `output/`.
- Stage directories reflect transformations performed by execution modules
- Data flows forward through the pipeline via clearly defined outputs
- Downstream modules consume outputs generated by upstream stages

This establishes a transparent mapping between pipeline stages and their outputs.

# Key Principle
Output organisation reflects data transformation through the pipeline.

Each directory represents a discrete processing step, and each file represents a deterministic result of that step.

# Execution Role
Execution modules are solely responsible for writing data to this directory.

Outputs must be:
- deterministic — identical inputs produce identical outputs
- clearly structured — directory layout reflects pipeline logic
- reproducible — results can be regenerated from the same inputs

# Rules
- Per-sample (or per-accession) directories are created within module scripts
- Pipeline-level directories are created during preflight
- Outputs must not depend on transient state (e.g. environment, ordering, or system context)
- Each module writes only to its own stage-specific directory

These rules ensure consistency and prevent unintended coupling between stages.

# Reproducibility
The `output/` directory is designed to support full reproducibility:
- output structure is fixed and predictable
- file naming is deterministic
- stage boundaries are explicit
- no hidden dependencies exist between outputs

Given the same inputs and pipeline version, the entire output/ directory can be recreated exactly.

# Summary
The `output/` directory provides a structured, stage-aligned representation of all data produced by the pipeline. 

Its design enforces clarity, modularity, and reproducibility, ensuring that outputs remain interpretable and consistent across executions.
